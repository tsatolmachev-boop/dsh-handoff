# Управление компьютером (Computer Control)

Host-плагин DSH для Windows: даёт модели инструменты `computer_*` для работы с реальным
рабочим столом. Плагин ставится в профиль и действует во всех его сессиях.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `computer_screenshot` | Снимок всего рабочего стола (или одного монитора) в PNG; путь возвращается, просмотр — через `read_image`. |
| `computer_windows` | Список видимых окон верхнего уровня: заголовок, процесс, PID, границы, свёрнуто/активно. |
| `computer_focus` | Вывести окно, в заголовке которого есть подстрока, на передний план. |
| `computer_move` | Переместить курсор в абсолютные координаты (физические пиксели). |
| `computer_click` | Клик левой/правой/средней кнопкой в текущей точке или в координатах. |
| `computer_type` | Ввести текст в сфокусированный элемент (Unicode SendInput), опционально Enter. |
| `computer_key` | Нажать комбинацию клавиш: `ctrl+s`, `alt+tab`, `win`, `ctrl+shift+esc` и т.п. |
| `computer_scroll` | Прокрутка колесом вверх/вниз (в текущей точке или в координатах). |
| `computer_clipboard` | Прочитать или записать текстовый буфер обмена. |

## Устройство

- `index.js` — Host-половина: регистрирует девять инструментов через `ctx.tools`.
  Импортирует только встроенные модули Node.js, поэтому работает из связанного
  (linked) локального пакета без зависимостей.
- `ps/*.ps1` — рабочие скрипты Windows PowerShell 5.1. Скрипты используют
  P/Invoke `user32.dll` (`SendInput`, `SetCursorPos`, `EnumWindows`, `SetForegroundWindow`)
  и System.Drawing для скриншотов. Все вызовы выполняются в дочернем процессе
  `powershell.exe` и не требуют прав администратора в обычном режиме.
- Результат каждого вызова пишется скриптом в UTF-8 JSON-файл, путь которого
  передаётся через переменную окружения `DSH_CC_RESULT`.

## Требования и ограничения

- Windows 10/11, Windows PowerShell 5.1 (есть в системе по умолчанию).
- Координаты — физические пиксели виртуального рабочего стола; `computer_screenshot`
  возвращает его размер и границы мониторов.
- `computer_focus` может не сработать, если Windows блокирует смену активного окна
  из фонового процесса (foreground lock). Скрипт использует стандартный обход —
  короткое нажатие Alt перед `SetForegroundWindow` — и повторяет попытку; если окно
  так и не стало активным, инструмент возвращает ошибку, а не ложный успех.
  Перед вводом текста/кликом стоит убедиться через `computer_windows`, что активное
  окно — нужное.
- Ввод на уровне UIPI не проходит в окна процессов с более высокими правами
  (например, в приложения, запущенные от администратора).
- Инструменты управляют реальным компьютером пользователя: клики и ввод могут
  изменить состояние приложений.

## Установка

Из сессии в профиле:

```text
plugin_manager({ action: "install_bundle", target: "<абсолютный путь к этой папке>" })
```

Плагин сам не чистит за собой: скриншоты лежат в `%TEMP%\dsh-computer-control\screenshots`
(хранятся последние 40), временные JSON-файлы удаляются после каждого вызова.

## Проверка

- `computer_screenshot` и `computer_windows` проверены вживую: снимок 2560×1600,
  список из 19 окон с корректными заголовками, процессами и координатами.
- `computer_focus`, `computer_click`, `computer_type`, `computer_key` вызываются без
  ошибок; сквозная проверка ввода (Блокнот + Ctrl+S) не удалась, потому что в этот
  момент пользователь активно переключал окна. Ограничение проверки, а не
  подтверждённый дефект: при повторной попытке без конкурирующей активности
  ввод стоит перепроверить.
- `computer_clipboard` не выполнялся, чтобы не перезаписать текущий буфер обмена.

Правки `ps/*.ps1` применяются сразу (скрипты читаются при каждом вызове), правки
`index.js` — только после перезапуска DSH (модуль уже загружен).
